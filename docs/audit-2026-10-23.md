# neocortex 0.1.4 — security & correctness audit

Read: AGENTS.md, design spec, all of `src/` and `tests/`, eval fixtures. Ran: `cargo fmt --check` (pass),
`cargo clippy --all-targets -D warnings` (pass), `cargo test` (151 pass, 1 ignored), `eval` on fixtures
(recall 0.953 / MRR 0.894) and holdout (0.924 / 0.789), `bench --n 10000` (recall p50 50 ms), plus the
reproductions marked **[ran]**. Everything below was run against copies under `/tmp`.

Both eval gates pass by <1% (fixtures 0.953 vs 0.95; holdout 0.924 vs 0.92, MRR 0.789 vs 0.78);
`aggregation` recall is 0.67 / 0.47 and holdout `paraphrase` MRR 0.46, so the average is carried by the
easy categories.

## Critical

1. **Unbounded MCP input wedges the whole server** — `src/mcp.rs:20,116` (only limit is 16 MiB/line),
   `src/extract.rs:746` (n-grams), `src/text.rs:479` (one FTS arm per token), `src/remember.rs:243`.
   A single request costs O(n) to O(n²): **[ran]** a 1 MiB `recall` query took **119 s** (returned nothing);
   225 KiB of capitalised `remember` content took **10.3 s** (the heuristic extractor plus a per-candidate
   full scan of `entities` at `src/resolve.rs:159-176` is O(n²)). 16 MiB → minutes to hours, and the server
   is single-threaded, so one agent stalls every other call.
   Fix: cap `content`/`query`/`entities`/`relations` at the tool boundary (32 KiB / 2 KiB / 64 items) and
   skip the gazetteer and heuristic extraction above the cap.

2. **`forget --hard` and `merge_entities` rebuild the entire graph** — `src/engine.rs:506,603` →
   `src/kg.rs:104` (one Cypher statement per memory, entity, mention, relation).
   **[ran]** deleting one memory from a 10k-memory DB took **245.9 s**; at the documented 50k-entity scale
   this is tens of minutes. `kg::remove_memory`/`remove_entity` already exist (`src/kg.rs:88,96`) and are
   never called. Fix: delete the one node/edge set with those helpers and project only affected relations.

3. **Opening a DB chmods any existing parent directory to 0700** — `src/db.rs:28-34` runs
   `set_permissions(dir, 0700)` on the parent whether or not this process created it.
   **[ran]** an existing 0755 directory became 0700 after `--db <dir>/mem.db`. `--db /tmp/mem.db` would
   chmod `/tmp`; `--db ./mem.db` in a shared checkout chmods the repo. Fix: only chmod a directory created
   here (or only the default `~/.neocortex`); never an arbitrary existing parent.

4. **`forget`/`supersede` never end the memory's relations, so "forgotten" facts stay current** —
   `src/engine.rs:507-514` (soft forget) and `src/remember.rs:391-398` (supersede) touch only `memories`.
   **[ran]** `remember "Mom lives in Delhi."` + relation, then `forget m1` → `recall` returns no memory but
   `facts: [r1 Mom→Delhi ended=false]`. Same after `supersedes`. This is the anti-goal "returning
   superseded facts as if current" and a privacy leak for `forget` (the design calls it "private").
   Fix: for relations evidenced only by the retired memory, set `expired_at`/`valid_to` (reuse
   `end_memories_of_ended_facts`).

5. **JSONL import can forget an unrelated live memory** — `src/export.rs:290-315`.
   **[ran]** live m1 "Important live memory."; import a line with the same content and `"expired":true`
   → `remember` returns `duplicate_of: m1`, then the post-pass calls `forget("m1")`; `live_memories` went
   1 → 0. Restoring a `--include-forgotten` export into a non-empty DB retires live rows.
   Fix: only run the expired post-pass when `out.duplicate_of.is_none()`.

6. **`import-remem` aborts midway on one bad row, leaving a partial import** — `src/import.rs:12-20`
   (one `remember` per row, no transaction) + `src/temporal.rs:76-82` (unix seconds ≤ 1e9 are rejected).
   **[ran]** a ReMem row with `created_at=0` → `invalid valid_from '0'`, exit 1, 1 of 3 rows imported,
   no rollback; re-running hits the same row. Fix: accept any non-negative unix second (or format ISO in
   `import.rs:68`) and wrap the whole import in one `Db::write`.

## High

7. **`as_of` is ignored by the graph channel** — `src/recall.rs:335` makes `as_of` imply `history`, and
   `src/kg.rs:164-204` then takes the `include_ended` branch, which never filters relations by `as_of`
   (it also admits future-dated ones). Relation seeds are built with `now` (`src/recall.rs:507-519`) and
   `relation_visible` short-circuits on `history`. Read-confirmed; the final `eligible()` filter still
   drops wrong *memories*, so the damage is PPR mass flowing through facts that did not exist at `as_of`
   (ranking dilution, not wrong rows). Fix: when `as_of` is set, filter edges by
   `valid_from <= t AND (valid_to IS NULL OR valid_to > t)` regardless of `history`.

8. **The exact-duplicate guarantee is not enforced** — `src/remember.rs:169-177` reads the hash before
   `db.write` at `:199`; `src/schema.sql:24` is a non-unique partial index. **[ran]** 12 concurrent
   identical `remember` calls produced 4 live copies of the same sentence. Fix: `CREATE UNIQUE INDEX ...
   ON memories(content_hash) WHERE expired_at IS NULL` and map the constraint error to `duplicate_of`.

9. **`merge_entities` breaks relation exclusivity and duplicates facts** — `src/engine.rs:570-587` moves
   `src`/`dst` with plain UPDATEs and never re-applies exclusive invalidation or dedupes.
   **[ran]** merging Alicia into Alice left both "Alice lives in Pune" and "Alice lives in Denver" live
   (`facts` shows both, `ended=false`), violating "at most one valid object per (src, predicate)".
   Merging two entities that both point at Pune leaves two identical live relations and `recall` prints
   the same fact twice. Fix: after the move, merge rows per `(src,predicate,dst)` and run the same
   exclusivity block as `remember`.

10. **Relation `valid_to <= valid_from` is accepted and silently hides the fact** —
    `src/remember.rs:294-301`; only memories are validated (`:73`). **[ran]** a relation
    `valid_from=2026-01-01, valid_to=2025-01-01` stores fine, then `recall` facts is empty (skipped by
    `src/recall.rs:844`). A typo silently loses the fact. Fix: same check as memories, naming the relation.

11. **`eval` panics on an empty query list and silently drops unknown expected keys** —
    `src/eval.rs:238` indexes `latencies[0]` when `latencies` is empty; `src/eval.rs:163-172` uses
    `filter_map` for `expect`. **[ran]** `{"queries":[]}` → panic, exit 101; a query expecting
    `["a","typo"]` scores recall **1.0 instead of 0.5**. (Today's fixtures have no stale keys, so the
    published numbers are not inflated.) Fix: guard empty latencies; error on an unknown key.

12. **Malformed model config panics the process** — `src/ultrabert.rs:154-155` indexes
    `rope_theta[i]`/`windows[i]` for `i in 0..24`. **[ran]** a 1-entry config → index-out-of-bounds panic.
    In MCP the lazy load runs inside `tools/call`, so the server dies. Fix: `get(i).ok_or_else(...)` and
    validate lengths in `from_files`.

13. **Export files and the SQLite WAL are world-readable** — `src/export.rs:250` uses `File::create`
    (0644 with umask 022); SQLite creates `-wal`/`-shm` 0644. **[ran]** `export --out` produced 0644 while
    the DB is 0600, and a live server held a 4.2 MB `mem.db-wal` at 0644 containing full memory text.
    The 0700 dir is the only mitigation and does not apply to relative `--db` paths or when chmod fails.
    Fix: `OpenOptions::mode(0o600)` for exports and chmod the WAL/SHM after opening (or umask 0077).

14. **`invalidate "12"` silently targets a memory, never a relation** — `src/engine.rs:142-146,426-461`.
    A bare id is tried as `m` first, so an agent meaning `r12` ends memory 12 instead. Fix: require the
    prefix for `invalidate`/`forget`, or reject a bare id that resolves to either.

15. **`content_hash` is never compared against content** — `src/text.rs:638-649`; the design promises
    "FNV-1a 64 + content compare". A hash hit is reported as `duplicate_of` and the new memory is dropped
    without comparing text (`src/remember.rs:169-177`). Fix: compare `kind` + `fold(content)` on the hit.

## Medium

16. **Eval ingestion bypasses the production supersede path** — `src/eval.rs:119-131` UPDATEs
    `expired_at/valid_to` directly, using `valid_to = now` instead of the superseding memory's
    `valid_from`, and never calls `end_memories_of_ended_facts`. The `current-vs-superseded` and `history`
    categories therefore do not exercise `remember` (so #4-class bugs cannot show up in eval). Fix: replay
    `supersedes` through a second `remember` pass.

17. **No schema migration path** — `src/db.rs:75-86` runs `schema.sql` (all `IF NOT EXISTS`) and then
    stamps `user_version` unconditionally. A future v2 binary will mark a v1 DB as v2 without adding
    columns. Only v>SCHEMA_VERSION is rejected. Fix: `match v { 0 => create, 1 => migrate(2), ... }` in one
    transaction before this ships with any schema change.

18. **Unbounded `limit`/`k` from MCP** — `src/mcp.rs:319,364`. `usize::MAX as i64 == -1`, and SQLite
    `LIMIT -1` means no limit (`src/recall.rs:901`); `entity` also calls `facts_for(..., usize::MAX)`.
    A huge `limit` returns the whole timeline/fact set. Fix: clamp `limit` to ~200 and `k` to 50.

19. **`facts_for` scans every relation on every recall and twice per `entity` call** —
    `src/recall.rs:824` selects all relations with no `WHERE` and filters in Rust; `entity` calls it twice
    (`:880-881`), `overview` once per community (`:1136`). It also `truncate`s in rowid order (`:858`), so
    the "top 8 facts" are the lowest relation ids, not the PPR-ranked facts the design promises.
    Fix: `WHERE r.src IN (...) OR r.dst IN (...)` and sort by `ppr[src]+ppr[dst]` before truncating.

20. **Temporal channel only considers the newest 400 rows in the window** — `src/recall.rs:427-429`.
    For "2020" or "since 2019" older in-window memories are never scored (design: brute force up to 5000,
    KNN beyond). Fix: count the window and use the documented threshold.

21. **The whole graph snapshot is rebuilt after every write** — `src/kg.rs:156-250` reads all memories,
    entities, mentions, relations and similar edges per generation. Measured at 10k: warm recall 49 ms,
    recall right after a write 70 ms (≈21 ms rebuild); ~200 ms at 100k. Fix: incremental invalidation, or
    per-table generations.

22. **Hard forget leaves dangling `superseded_by`** — `src/engine.rs:505` deletes the row but never clears
    references. **[ran]** after hard-deleting m2, `recall --history` shows `[superseded by m2]` for m1,
    which can never be restored. Fix: `UPDATE memories SET superseded_by=NULL WHERE superseded_by=?1`.

23. **`NEOCORTEX_TZ=Europe/Berlin` silently means UTC, and DST is frozen** — `src/temporal.rs:317-322`
    (`parse_offset` returns None → `unwrap_or(0)`) and `:327` (offset sampled once per process, documented).
    Fix: reject an unparsable value with a message instead of silently using 0.

24. **`Db::write` leaves the transaction open if COMMIT fails** — `src/db.rs:100-112` returns the error
    without `ROLLBACK`, so the next write fails with "cannot start a transaction within a transaction".
    Fix: roll back on the commit error too.

25. **`communities()` writes outside a transaction on the read path** — `src/kg.rs:285-297` (DELETE + N
    INSERTs) and is called by `overview`; a crash/concurrent call leaves a mixed table and the write can
    fail the read with SQLITE_BUSY. `communities_gen` is written but never read (dead), and Louvain runs on
    every `overview` (`:252`). Fix: cache on `communities_gen`, or move it into `Db::write`.

26. **`recall` writes `access_count` outside a transaction** — `src/recall.rs:706-717`; a read-only DB
    makes recall fail, and concurrent recalls contend for the write lock. Fix: best-effort / ignore errors.

27. **`overview` is N+1 per entity** — `src/recall.rs:1105-1110` runs one query per entity in every
    community, plus `representative()` per community. At 10k it is 0.3 s; it scales linearly with entities.

## Dead code / duplication worth deleting

- `kg::remove_memory`, `kg::remove_entity` (`src/kg.rs:88,96`) — unused; exactly what #2 needs.
- `text::trigram_jaccard` (`src/text.rs:242`) — tests only; the design's "trigram blocking" is actually a
  3-char prefix scan (`src/resolve.rs:138-149`), so lexical merges miss candidates outside KNN/prefix.
- `text::fts_query` (`src/text.rs:474`) — tests only (production uses `fts_query_with`).
- `eval::ablation` (`src/eval.rs:427`) — unused (main builds variants itself).
- `engine::OptionalRow` (`src/engine.rs:807`) — reimplements `rusqlite::OptionalExtension`, used once.
- `recall::blob_vec` vs `resolve::blob_to_vec` — duplicate f32-blob decoders.
- `kg::communities_gen` — written, never read.

## Also noted (low)

- `parse_instant` rejects unix seconds < 1e9 (`src/temporal.rs:76-82`); pre-2001 dates need ISO.
- `remember` dedupes on `kind+content` only, ignoring `scope` (`src/remember.rs:168`); the same sentence in
  two scopes collapses into one memory (by design, but surprising for `scope` users).
- `entity("12")` parses as e12 without an existence check and fails with a raw "Query returned no rows"
  (`src/engine.rs:142`, `src/recall.rs:863`).
- `unsafe` blocks are the expected ones: sqlite-vec `transmute` (`src/db.rs:17-23`) and
  `from_mmaped_safetensors` (`src/ultrabert.rs:112`); the latter is UB if the model file is rewritten
  while the server holds the map.
- `NEOCORTEX_MAX_TOKENS` is unbounded and sizes tensors/masks directly (`src/embed.rs:122-125`).
- The `cypher` read-only check is a word blacklist (`src/engine.rs:757-768`), not a parser; CLI-only, so
  acceptable, but `CALL`-style writes should be rejected by the engine if this is ever exposed.
